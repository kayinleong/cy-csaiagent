## Resolution (2026-06-08 — quick-kayinleong-005, commit `d01fce4`)

The single critical integration gap is **closed**. The Reply and Finder agents emit their output
as a JSON object in the final assistant text; the client never decoded it, so Reply turns rendered
as raw-JSON bubbles (`ReplyDraftCard` never showed) and the Finder `MatchList` — defined but never
wired into `message-list.tsx` (the audit's "suspected related") — never rendered either. The fix
added a pure `app/[lang]/chat/decode-structured-output.ts` (`decodeReplyOutput`/`decodeFinderOutput`),
wired a `pillarOverride`-gated decode on stream completion in `chat-input.tsx` (attaching
`replyOutput`/`finderOutput` to the assistant message), and added the `MatchList` render branch +
`finderOutput` field to `message-list.tsx`. 14 new unit tests cover the decode gate and per-pillar
non-collision. Gates at HEAD: `tsc` 0 errors · `vitest` 555 pass / 0 fail · `eslint` 0 errors on
touched files. This moves integration to **14/14**, E2E flows to **6/6**, and unblocks the 6 partial
Reply requirements at code level. Live browser click-through of the rendered cards remains a
rollout-prep gate (no local Firebase creds). All 5 phase CLAIMs are now closed (`done`).
