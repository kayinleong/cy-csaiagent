## Trust Boundaries
| Boundary | Description |
|----------|-------------|
| client → /api/chat | Untrusted message content + langOverride + cid cross here; gates (auth/ratelimit/PDPA) run before any model spend. |
| client → Server Actions (handoff, disclosure-ack) | Mutations re-verify the user via the session cookie. |
| handoff bundle → escalations | Context bundle must carry references/pseudonyms only, no raw PII. |

## STRIDE Threat Register
| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-10 | Spoofing | cid / langOverride in body | mitigate | uid comes from requireUser (verified token), not the body; cid for the primary thread is derived server-side as `coach-${uid}`; an arbitrary client cid is still rules-gated to ownerUid on read. |
| T-02-11 | Info-disclosure | handoff contextBundle | mitigate | Bundle stores {conversationId, journeyStage, rollingSummary} — references/summaries only, no raw lead PII (T-01-36); pseudonymize gate already applied to message content upstream. |
| T-02-12 | Tampering | langOverride forcing wrong-lang grounding | accept | Worst case is a wrong-language reply for the agent's own training query; no security impact; agent can re-toggle. |
| T-02-13 | Repudiation | who saw the AI disclosure | mitigate | disclosureAckAt persisted to users doc (audit-traceable) in addition to localStorage. |
| T-02-14 | Info-disclosure | citation chunkIds in history | accept | chunkIds are internal KB references, not PII; persisting them is required for grounding evidence (Pitfall 6). |
</threat_model>
