<threat_model>
## Trust Boundaries
| Boundary | Description |
|----------|-------------|
| coach browser → dashboard RSC | Role-gated read of downline data; reads run server-side with an explicit downline filter. |
| coach → conversation/agent data | Drilldown into agent data; must be downline-scoped + audit-logged (PDPA). |
| coach correction → KB | A coach injects content into the KB; attributed, versioned, no privileged bypass. |

## STRIDE Threat Register
| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-28 | Info-disclosure/Elevation | cross-coach downline read | mitigate | Every query applies `where('seniorCoachId','==',coach.uid)` server-side; rules (02-01) are the second gate; cross-coach exclusion is unit-tested (Task 1). |
| T-02-29 | Info-disclosure | coach reading agent data without trace | mitigate | `auditDrilldown` writes a hashes-only audit row on every downline read (TSD §5.1); no raw transcript client rule added (A6). |
| T-02-30 | Tampering | inline correction injecting bad KB content | mitigate | correctKbDoc attributes `correctedBy`; same chunker (no privileged path); admin oversight via versioning (supersedesId); old version superseded not deleted (auditable). |
| T-02-31 | Spoofing | role/uid from client on dashboard | mitigate | uid + role from requireUser (verified token via session cookie), never from the page params/body. |
| T-02-32 | Info-disclosure | knowledge-gap feed leaking PII | mitigate | Feed reads knowledgeGaps which stores topicLabel/hash only (02-05); no raw query text reaches the UI. |
</threat_model>
