<threat_model>
## Trust Boundaries
| Boundary | Description |
|----------|-------------|
| client → Firestore (rules) | A signed-in coach/agent reads collections directly from the client; rules are the only gate. |
| client → /api/auth/session | Untrusted idToken crosses here; server verifies before issuing a role + cookie. |
| provisioning script → Admin SDK | set-claims assigns role + downline relationship; privileged, run by an operator only. |

## STRIDE Threat Register
| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Elevation/Info-disclosure | knowledgeGaps + agentProfiles reads | mitigate | Rules require `seniorCoachId == request.auth.uid && sameTenant()`; cross-coach denied-case is rules-unit-tested (Task 2e). |
| T-02-02 | Spoofing | sign-in role redirect | mitigate | Role read ONLY from the server's `/api/auth/session` verifyIdToken response — never from a client-set value; the redirect is UX only, every Firestore read is independently rules-gated. |
| T-02-03 | Tampering | knowledgeGaps writes | mitigate | `create, update, delete: if false` — server/Admin-SDK writes only (same posture as escalations/auditLogs). |
| T-02-04 | Info-disclosure | cross-tenant read | mitigate | `sameTenant()` on every new rule; converter stamps tenantId on every write. |
| T-02-05 | Info-disclosure | published-chunk index | accept | The lang+status+embedding index itself leaks nothing; the retrieval filter that uses it is built+tested in 02-02. |
</threat_model>
