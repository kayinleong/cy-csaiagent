## Trust Boundaries

| caller (Server Action, 05-05) → eraseDataSubject | The actor uid + reqId arrive from an admin-gated caller; this module trusts them (gate is the caller's job + verified token) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-COVERAGE | Information Disclosure | a PII collection missed by erasure (residual PII = PDPA breach) | mitigate | Single PII_ERASURE_MANIFEST drives executor + sweep + the seeded-subject coverage test asserting 0 docs in EVERY collection (Pitfall 1) |
| T-05-AUDIT | Repudiation | the audit log destroyed by the erasure cascade | mitigate | auditLogs in the EXEMPT list, skipped by construction (never queried for deletion); coverage test asserts auditLogs SURVIVES + an `erasure` event is written (Pitfall 2) |
| T-05-MEGADELETE | Denial of Service | a synchronous full cascade over an 800-message thread hits the 60s/Cloud-Run timeout | mitigate | Bounded synchronous batch + the chunked erasure-sweep lazy-cron finishes the rest within the 1h window / 72h SLA (Pitfall 10, D-02) |
| T-05-DOUBLESWEEP | Tampering | two concurrent visitors both run the sweep window (race) | accept→mitigate | runJob's txn DUE-gate gives exactly-once-per-window; sweep is idempotent (deleting a gone doc is a no-op) so even a race is safe (Pitfall 3) |
| T-05-RAWID | Information Disclosure | raw subject id stored on the request doc | mitigate | ErasureRequestDoc stores subjectIdHash only (05-02 schema); the erasure event hashes all raw values |
