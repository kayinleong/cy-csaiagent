<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser (admin) → erasure Server Action | Admin triggers an irreversible destructive write; role must come from the verified token, not the request body |
| client form → Server Action | The type-to-confirm token is a UX guard; the SERVER re-validates admin + zod (the dialog is not the security boundary) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-ADMINGATE | Elevation of Privilege | a non-admin invoking eraseDataSubject | mitigate | Three-layer gate (layout → page redirect → Server Action `role !== 'admin'`); role from verified token only; the action test asserts Forbidden/Unauthorized |
| T-05-ACCIDENT | Tampering (accidental destructive action) | a single click erasing a subject | mitigate | HR-8/HR-9 type-to-confirm: destructive AlertDialogAction disabled until typed token === subject ref; "Erase…" only opens the dialog |
| T-05-RAWID | Information Disclosure | raw subject id persisted | mitigate | erasureRequests stores subjectIdHash only; the erasure event hashes all raw values |
| T-05-INPUT | Tampering | malformed/forged action input | mitigate | zod Input.parse before any Admin-SDK write (V5); reject non-enum subjectType |
| T-05-BLAST | Information Disclosure | blast-radius preview leaking PII | mitigate | Preview returns COUNTS only (AggregateField.count), audited via auditDrilldown |
</threat_model>
