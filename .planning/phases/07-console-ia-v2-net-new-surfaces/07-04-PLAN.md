<objective>
Build the conversation flagged queue (D-25 → Conversations & Escalations): a content-free flag mechanism (`flagConversation` Server Action over the `conversationFlags` collection from 07-02) plus a coach-or-admin queue view with review/dismiss actions. Manual flagging only — no AI auto-flagging (D-11). The flag carries a `conversationId` reference only (D-10); the queue deep-links to the EXISTING audited conversation viewer for content.

Purpose: Give coaches/admins a triage surface for conversations needing review, without duplicating any PII onto the flag (the existing audited viewer remains the single content surface). Turns the Wave-0 FLAG-02/FLAG-03 contracts green.
Output: flagConversation action + a "Flag conversation" affordance on the admin viewer; flags/ queue (list + review/dismiss) under the (coach) route group.

ROUTING NOTE (verified): the flagged queue is coach-or-admin (D-11) → `(coach)` route group (admits senior-coach + admin). The existing conversation viewer is admin-only (`(admin)/conversations/page.tsx:58` gates `user.role !== 'admin'`) and reads full PII content — do NOT widen it to coaches. The admin "Flag conversation" button lives on that admin viewer (admin flag path). The `flagConversation` action itself is coach-or-admin gated so a coach CAN create a flag for an own-downline conversationId from a coach-reachable reference (e.g. a downline conversation id surfaced in the coach dashboard); the action enforces own-downline at write time. No coach gains read access to conversation content through this plan.
</objective>
