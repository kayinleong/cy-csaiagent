# Phase 7 — UI Design Contract

>

## Spacing Scale

Declared values (Tailwind 4 default 4px-base scale — matches the live `gap-4`/`gap-6`/`py-8`/`mb-4` usage in `usage-dashboard.tsx`):

| Token | Value | Tailwind | Usage |
|-------|-------|----------|-------|
| xs | 4px | `gap-1` / `p-1` | Icon-to-label gaps, badge inner padding |
| sm | 8px | `gap-2` / `p-2` | Compact element spacing, table cell padding |
| md | 16px | `gap-4` / `p-4` | Default element spacing, card padding, toolbar gaps |
| lg | 24px | `gap-6` / `p-6` | Card grid gaps, section padding (the dashboard `grid gap-6` standard) |
| xl | 32px | `py-8` | Empty-state vertical padding, major in-page section breaks |
| 2xl | 48px | `py-12` | Page-level top/bottom rhythm on standalone surfaces |
| 3xl | 64px | `py-16` | Reserved — full-page empty/error states only |

**Section heading rhythm:** `mb-4` (16px) below an `h2` section heading before its content (live convention, `usage-dashboard.tsx:237`).

Exceptions:
- Icon-only action buttons (row actions in tables: review/dismiss/edit) use the shadcn `Button size="icon"` default (36px box) — touch target is acceptable for a desktop-primary console. Where a row action is the only tap target on a narrow viewport, wrap in a `size="sm"` text+icon button (≥44px width) rather than icon-only.
- Metric tiles use `text-2xl` numerals inside `gap-6` grids (the established Analytics tile rhythm) — do not invent a tighter metric grid.

## Typography

Use Tailwind type utilities only — these map to the sizes already in use across `(admin)`/`(coach)` surfaces. Exactly 4 roles, exactly 2 weights.

| Role | Size | Tailwind | Weight | Line Height |
|------|------|----------|--------|-------------|
| Body / table cell / label | 14px | `text-sm` | regular 400 | 1.5 (`leading-normal`) |
| Section heading (h2) | 18px | `text-lg` | semibold 600 (`font-semibold`) | 1.4 |
| Metric / page title (h1) | 24px | `text-2xl` | bold 700 (`font-bold`) — metrics; `font-semibold` for page titles | 1.2 (`leading-tight`) |
| Page eyebrow / breadcrumb / helper / em-dash empty | 14px | `text-sm` | regular 400 | 1.5 |

**Weights:** exactly two — regular (400) for all body/label/helper text; semibold (600) for headings + emphasis. `font-bold` (700) is permitted ONLY on `text-2xl` metric numerals (the established `usage-dashboard.tsx` metric pattern), not on prose.

**Mono usage:** `font-mono` `text-sm` for machine values that must be read verbatim — `targetRef` and `actorUid` in the audit-log viewer, the current/new model-id strings in model-config, hashed-value displays. Mono never used for prose or labels.

## Color

Neutral grayscale OKLCH palette (detected in `app/globals.css`). This is a near-monochrome admin console — there is intentionally almost no chromatic accent; hierarchy comes from weight, size, and surface elevation, not hue. Do NOT introduce a brand color.

| Role | Token | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` (`bg-background`) | Page background, primary surface |
| Secondary (30%) | `--card` / `--secondary` / `--sidebar` (`bg-card`, `bg-sidebar`) | Cards, metric tiles, sidebar, table containers, dialogs |
| Accent (10%) | `--primary` (`bg-primary` / `text-primary`) | See reserved-for list below |
| Destructive | `--destructive` (`text-destructive` / `bg-destructive`, `variant="destructive"`) | Destructive/sensitive confirmations only |

**Accent (`--primary`) reserved for — explicit list (never "all interactive elements"):**
- The single primary CTA per surface (e.g. "Create cohort", "Publish change", "Record first close", "Save assignment").
- The active/selected nav item in the sidebar (existing `--sidebar-primary` behavior — inherited, do not restyle).
- Focus rings (`--ring`) and the active row/selection indicator in tables.

Everything else (secondary buttons, filters, table chrome, badges-by-default) uses `secondary`/`outline`/`ghost` variants in neutral tones.

**Status semantics for the flagged queue + audit surfaces** — use `Badge` variants, NOT new colors:
- `open` flag → `Badge variant="default"` (neutral-strong) — needs attention but not an error.
- `reviewed` → `Badge variant="secondary"` (muted) — resolved-positive.
- `dismissed` → `Badge variant="outline"` with `text-muted-foreground` — closed-neutral.
- Destructive verbs (cohort delete) → `text-destructive` only inside the confirm dialog, never as a resting-state row color.

**Hard rule:** `--destructive` is reserved for genuinely destructive/irreversible-leaning actions (cohort delete). A model-config publish is reversible (D-16) → it uses the **neutral primary** confirm, NOT destructive red. Coach reassignment is reversible → neutral primary confirm.

## Copywriting Contract

All strings are **trilingual EN / BM / 中文** (D-26) — every key below ships in all three `next-intl` catalogs (en/ms/zh) and `i18n-parity.test.ts` must stay green. Copy below is the **EN source**; BM/中文 are authored to parity and await native sign-off (carry the Phase-6 native-sign-off gate). No string is hard-coded in a component.

**Voice:** plain, operator-facing, verb-first on actions. No marketing tone. No send/connect/WhatsApp/auto-reply language anywhere (the No-WABA / No-auto-send v1 constraint is in force — see Constraints).

### Primary CTAs (one accent CTA per surface)

| Surface | Primary CTA (EN) |
|---------|------------------|
| Cohort management (S1) | "Create cohort" / row: "Edit cohort" |
| Agent profile (S2) | — (read-only; no primary write CTA) |
| Coach-assignment (S3) | "Save assignment" (confirm dialog: "Reassign coach") |
| Flagged queue (S4) | from viewer: "Flag conversation"; queue rows: "Mark reviewed" / "Dismiss" |
| Audit-log viewer (S5) | — (read-only; "Load more" pagination control only) |
| Model-config (S6) | "Publish change" (confirm dialog: "Publish model change") |
| PDPA-settings (S7) | — (read-only; "Open erasure flow" link-button only) |
| days-to-first-close (S8) | "Record first close" |

### Empty states (em-dash + Empty primitive convention)

For **metric values** that are absent, render the literal em-dash `'—'` (the live `usage-dashboard.tsx` convention) — NOT "0", NOT "N/A".

For **list/table empties**, use the `Empty` primitive with this copy:

| Surface | Empty heading | Empty body (+ next step) |
|---------|---------------|--------------------------|
| Cohorts (S1) | "No cohorts yet" | "Create a cohort to group agents by intake batch or team." |
| Agent profile (S2) — no usage | metric tiles show `—` | (no list-empty; absent fields render `—`, e.g. "No close recorded yet" for days-to-first-close) |
| Flagged queue (S4) | "No flagged conversations" | "Flagged conversations from the viewer appear here for review." |
| Audit log (S5) | "No matching audit entries" | "Adjust the action, actor, or date filters to widen the search." |
| Model-config (S6) | (never empty — 5 pillars always listed; a key with no published value shows its fallback as a hint) | helper: "Showing the offline fallback — no value published yet." |
| days-to-first-close (S8) | aggregate shows `—` | "No first-close recorded for this cohort yet." |

### Loading states

Tables and metric grids use the `Skeleton` primitive (row skeletons for tables, tile skeletons for metric grids) during server fetch — never a bare spinner for tabular data. Action buttons show an inline `Spinner` + disabled state while a Server Action is in flight.

### Error states (problem + what to do next)

| Context | Error copy |
|---------|------------|
| Server Action denied (role) | "You don't have permission to perform this action." (the surface should already be gated server-side; this is the defense-in-depth toast) |
| Model-config ETag conflict (D-16) | "This setting changed since you opened it. Reload to see the latest value, then publish again." (offer a "Reload" action — never blind-overwrite) |
| Remote Config propagation note (D-15) | After a successful publish: "Published. Changes may take a moment to take effect." (do NOT claim instant) |
| Record-first-close already set (D-21) | "A first close is already recorded for this agent. Only an admin can override it." |
| Firestore index still building (D-pitfall-6) | "This view is still preparing. Try again in a few minutes." (graceful, not a raw `FAILED_PRECONDITION`) |
| Generic Server Action failure | "Something went wrong. Your change wasn't saved — please try again." |

### Destructive / sensitive confirmations

All sensitive writes use shadcn `AlertDialog` (never a bare `confirm()`). Type-to-confirm is NOT used for any Phase-7 action (reserved for erasure, which is Phase 5 — every Phase-7 sensitive write is reversible). Each confirm dialog names the action and states the consequence:

| Action | Confirm dialog title | Body | Confirm button |
|--------|----------------------|------|----------------|
| Cohort delete (S1) | "Delete cohort?" | "Agents in this cohort will be unassigned. This can't be undone." | "Delete cohort" (`variant="destructive"`) |
| Coach reassignment (S3) | "Reassign coach?" | "{agent} will be moved to {new coach}. Past analytics keep their original coach." (states the D-08 denorm behavior) | "Reassign coach" (neutral primary) |
| Model publish (S6) | "Publish model change?" | "{pillar} will use {new model id} for new requests. You can change this again at any time." | "Publish change" (neutral primary — reversible) |
| Record first close (S8) | "Record first close?" | "This sets the agent's first-close date and can't be changed without an admin." | "Record first close" (neutral primary) |
| Flag dismiss (S4) | "Dismiss flag?" | "This closes the flag without further review." | "Dismiss" (neutral primary) |

## Interaction & Layout Contract (per surface)

Desktop-primary, responsive-down (these are admin/coach console surfaces, not the mobile chat surface). All surfaces slot under existing Phase-6 sections (D-25) with role-filtered nav entries; the **server-side `requireRole()` gate is the authorization boundary — nav filtering is UX-only** (D-24). **Read-only role is DENIED on ALL 8 surfaces** — none appears in the read-only nav and none is reachable by a read-only session.

| # | Surface | Section | Primitives | Pattern (match analog) |
|---|---------|---------|-----------|------------------------|
| 1 | Cohort management | Agents & Cohorts | `table` + `dialog` + `form`/`field` + `alert-dialog` | List page + create/edit dialog; mirrors `roles/page.tsx` admin-assignment shape |
| 2 | Agent profile | Agents & Cohorts | `card` grid + `badge` + metric tiles + `separator` | Composed read view; metric tiles mirror `usage-dashboard.tsx`; no edit affordance anywhere |
| 3 | Coach-assignment | Agents & Cohorts | `combobox`/`select` + `alert-dialog` | Single reassign control + confirm; mirrors `roles/page.tsx` |
| 4 | Flagged queue | Conversations & Escalations | `table` + `badge` (status) + `dialog` (flag-reason) + row actions; viewer gets a "Flag conversation" button | Flag action lives on the existing `conversation-viewer.tsx`; queue is a new list; rows deep-link to the existing audited viewer (no content stored on flag, D-10) |
| 5 | Audit-log viewer | System & Compliance | `table` + filter toolbar (`select` + date inputs) + `pagination` ("Load more") | Bounded cursor read (limit 50); `font-mono` for `actorUid`/`targetRef`; hashes shown raw, never decoded (D-12) |
| 6 | Model-config | System & Compliance | `card` per pillar + `input` (free-form) + `alert-dialog` confirm + toast | 5 pillar rows; current value as placeholder/hint; ETag-conflict + propagation copy (above); NO send/connect framing |
| 7 | PDPA-settings | System & Compliance | `card` + definition rows (`dl`-style) + link-button | Static read-only policy display from a policy-constants module; "Open erasure flow" links to the existing Phase-5 erasure surface; zero editable inputs (D-18) |
| 8 | days-to-first-close | Analytics & Performance | metric tile (added to `usage-dashboard`) + `alert-dialog` for "Record first close" | Aggregate avg/median tile in Analytics; per-agent value on the S2 profile; em-dash when no close yet |

**Cross-surface UX invariants:**
- Toast feedback (sonner) on every successful Server Action; inline field errors via `form`/`field` for validation.
- Tables: header row, zebra-free (shadcn default), `text-sm` cells, right-aligned numeric columns, row hover via theme token; bounded reads only (limit 50) — never fetch-all.
- Every page has a breadcrumb reflecting its Phase-6 section (D-25 placement); the section label and page title are trilingual.
- No surface renders any "send", "connect WhatsApp", "auto-reply", or outbound-message affordance.
