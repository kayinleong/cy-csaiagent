## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → Firestore (new collections) | Untrusted client reads/writes cross into cohorts + conversationFlags; rules are the boundary |
| Server Action (Admin SDK) → Firestore | Admin SDK bypasses rules; the `create,update,delete: if false` posture forces ALL flag writes through the audited Server Action |
| coach token → conversationFlags row | A coach must only read flags whose denormalized seniorCoachId == their verified uid |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01 | Elevation of Privilege | read-only reaching cohorts/conversationFlags | mitigate | No read-only grant in either rule block (D-24); RO-01 matrix proves DENY (Task 2) |
| T-07-02 | Information Disclosure | cross-coach flag read | mitigate | `resource.data.seniorCoachId == request.auth.uid` read rule (mirrors escalations); cross-coach FAILS in tests |
| T-07-03 | Tampering | client forges/mutates a flag | mitigate | `allow create, update, delete: if false` on conversationFlags (Admin-SDK only, D-09) |
| T-07-05 | Tampering | client writes a cohort | mitigate | cohorts `allow write: if hasRole('admin') && incomingTenant()` (D-03); non-admin write FAILS |
| T-07-06 | Information Disclosure | cross-tenant read of a new collection | mitigate | `sameTenant()` on every read rule; `incomingTenant()` on cohort writes; makeConverter auto-stamps tenantId |
