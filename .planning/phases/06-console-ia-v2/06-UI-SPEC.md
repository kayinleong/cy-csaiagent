# Phase 6 — UI Design Contract: Console IA v2 (Restructure + Read-only Role)

> Visual and interaction contract for the console restructure. This is a **brownfield restructure of an existing console** — the design system (Tailwind 4 + vendored shadcn/ui) is FIXED. This spec specifies the *new/changed* UI only and references existing components verbatim everywhere else. The single most important constraint: **no regression to any v1 feature.**
>
> Generated by gsd-ui-researcher; verified by gsd-ui-checker. Upstream: `06-CONTEXT.md` (LOCKED decisions), `06-RESEARCH.md` (codebase-grounded), `SCOPE.md` (gap audit).

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn (already initialized; all components vendored in `components/ui/`) |
| Preset | not applicable — vendored manually; Tailwind 4 `@theme inline` tokens in `app/globals.css` |
| Component library | radix-ui + @base-ui/react (per `CLAUDE.md`); shadcn wrappers in `components/ui/` |
| Icon library | `lucide-react` (already used in `app-sidebar.tsx`) |
| Font | `--font-sans` (Geist Sans) body/heading; `--font-mono` (Geist Mono) for IDs/UIDs |
| Theme model | neutral OKLCH grayscale (`:root` + `.dark`); recharts series override to indigo/amber (see Color) |

**Rule:** Reuse, do not reinvent. Every surface in this spec is a re-composition of existing components + existing server queries. The only genuinely-new presentation is the 6-section sidebar grouping, the Home grid, the read-only viewer variant, the per-coach pivot control, and the Integrations placeholder.

## Color

The theme is a **neutral OKLCH grayscale** system. There is NO chromatic brand accent in the surface chrome — `--primary` is near-black (`oklch(0.205 0 0)`) in light mode. Chroma appears ONLY inside recharts data series (indigo `#6366f1` primary, amber `#f59e0b` secondary — established in `usage-dashboard.tsx` / `metrics-panel.tsx`). Honor that split.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` `oklch(1 0 0)` light / `oklch(0.145 0 0)` dark | page background, content area |
| Secondary (30%) | `--sidebar` `oklch(0.985 0 0)` + `--card` | sidebar, nav, all cards/widgets |
| Accent (10%) | `--primary` `oklch(0.205 0 0)` | active nav item (`data-active` → `bg-sidebar-accent`), KPI numerals, primary buttons, current-version highlight (`border-primary bg-primary/5`) |
| Destructive | `--destructive` `oklch(0.577 0.245 27.325)` | NONE in Phase 6 — read-only role + restructure introduce no destructive actions. Erasure (the one destructive surface) is RELOCATED verbatim, not redesigned. |

**Accent reserved for:** active-route indication in the sidebar (vendored `isActive` → `data-active:bg-sidebar-accent`), KPI value numerals, the "current version" row highlight in the version-history viewer, and primary action buttons. Never used as a decorative fill on cards or section chrome.

**Data-viz palette (charts only, do not change):** primary series `#6366f1`, secondary series `#f59e0b`, grid `#f0f0f0`, bar radius `[4,4,0,0]`, `ResponsiveContainer height={220}`, axis `tick fontSize 12`. The per-coach pivot reuses these verbatim.

## 1. Six-Section Navigation Structure (IA-01)

**Approach (LOCKED):** Regroup the sidebar into 6 sections **over the existing routes**. Do NOT physically move route folders (avoids deep-link breakage + layout-gate mismatch — CONTEXT + RESEARCH Pitfall 1/anti-pattern). Existing `href`s are unchanged. The 6 section names are **business-fixed and immutable**.

**Component:** Extend `app/[lang]/_components/app-sidebar.tsx`. Keep `<Sidebar collapsible="icon">`. Render **one `SidebarGroup` per section**, each with a `SidebarGroupLabel`, wrapping a `SidebarGroupContent > SidebarMenu`. Use the existing `SidebarMenuItem` + `SidebarMenuButton asChild isActive={isActive(href)} tooltip={t(key)}` pattern verbatim (it already supplies the collapsed-mode tooltip and the active state).

**Section order + members (existing surfaces relocated; hrefs unchanged):**

| # | Section (`SidebarGroupLabel`) | Nav items (existing route → unchanged `href`) | Icon (lucide) |
|---|-------------------------------|------------------------------------------------|---------------|
| 1 | **Home** | Home `/${lang}` (new RSC landing) | `Home` |
| 2 | **Knowledge Management** | Knowledge Base `/${lang}/kb` · Inventory `/${lang}/inventory` | `BookOpen` · `Building2` |
| 3 | **Agents & Cohorts** | Agents `/${lang}/dashboard` (relocated downline/agent list only — cohorts are Phase 7) | `Users` |
| 4 | **Conversations & Escalations** | Conversations `/${lang}/conversations` · Escalations `/${lang}/dashboard#stalls` (stall inbox — see note) | `MessagesSquare` · `AlertTriangle` |
| 5 | **Analytics & Performance** | Usage & Cost `/${lang}/usage` · Coach Analytics `/${lang}/dashboard` (funnel/ramp/gaps panels) | `BarChart3` · `LineChart` |
| 6 | **System & Compliance** | Roles & Permissions `/${lang}/roles` · Integrations `/${lang}/integrations` (new shell) · Erasure `/${lang}/erasure` | `ShieldCheck` · `Plug` · `Trash2` |

**Note on the dashboard appearing in 3 sections:** the existing `(coach)/dashboard` page bundles downline list (→ Agents), stall inbox (→ Escalations), and funnel/usage panels (→ Analytics). Phase 6 does NOT split the route. Planner's discretion (CONTEXT): either (a) keep one `/dashboard` route and let Agents/Escalations/Analytics nav items deep-link to in-page anchors, OR (b) introduce thin route-group siblings that re-compose the existing `_components/*` panels (no logic duplication, panels imported as-is). EITHER way, no panel logic is rebuilt and no existing deep link breaks. The nav `href` table above assumes option (a) as the lowest-risk default; if (b) is chosen the planner updates hrefs but keeps the same section grouping.

**Collapsed/expanded behavior:**
- Sidebar uses vendored `collapsible="icon"`. Collapsed = icon rail; `SidebarGroupLabel` auto-hides (`group-data-[collapsible=icon]:opacity-0`); each item shows its `tooltip` on hover. No custom collapse logic needed — the primitive handles it.
- Sections are visually grouped by label + the vendored group spacing; they are NOT independently collapsible accordions in v1 (keeps parity with the current flat sidebar's interaction model and avoids hiding role-filtered items behind a toggle). If a section has **zero** visible items for the current role, render NOTHING for that section (no empty label).
- Header (`SidebarHeader` app name) and footer (`signedInAs {role}`) unchanged.

**Active-state pattern (unchanged):** `isActive(href) = pathname === href || pathname.startsWith(\`${href}/\`)` → drives `data-active:bg-sidebar-accent data-active:font-medium`. For anchor-style deep links (`#stalls`), active state keys off the base route only.

**Broken-link fix (Pitfall 1 — MANDATORY when touching KB):** `kb-doc-list.tsx:188` and `kb/[docId]/page.tsx:138,178` link to `/${lang}/admin/kb/...`; `(admin)` is a route group and never appears in the URL. Fix to `/${lang}/kb/...`. This is a UI correctness fix in scope for this phase.

## 3. Home Surface Layout (HOME-01)

**Constraint (LOCKED):** Compose ONLY from existing aggregations. No new lazy-cron jobs, no new pipelines, all reads server-side (RSC via Admin SDK). Sources: `usageRollups` (NOT raw `usageEvents`), the stall inbox query, knowledge-gap aggregation, funnel — exactly the queries already backing `usage/page.tsx` and `dashboard/actions.ts`.

**Route:** new RSC at `app/[lang]/page.tsx` becomes the Home landing (replacing the pure redirect for console roles). Keep the redirect for `new-agent` → `/chat`. Read-only, senior-coach, admin → render Home. Resolve role inside try/catch, `redirect()` OUTSIDE (RESEARCH Pitfall 6).

**Layout — responsive widget grid (match existing card conventions):**
```
container mx-auto max-w-6xl px-4 py-8
  H1  "Home"  + muted subtitle (role-aware: "Org overview" / "Your downline" / "Reporting overview")
  [stale watchdog Alert — reuse usage-dashboard pattern, shown if latest rollup is stale]
  grid gap-8:
    Section A — Key Metrics:   grid gap-6 grid-cols-2 md:grid-cols-4   (KPI Cards, identical to usage-dashboard tiles)
    Section B — Alerts:        Card list (open stalls count + knowledge-gap count)   [role-gated]
    Section C — Recent activity: Card with a compact list (latest rollup window summary / recent KB versions)
    Section D — Quick actions:  grid gap-6 grid-cols-2 md:grid-cols-3  (Button-as-Link tiles to the user's allowed sections)
```

**Per-role Home variant:**

| Block | admin | senior-coach | read-only |
|-------|-------|--------------|-----------|
| A Key metrics | org KPIs from `usageRollups` (active agents, message volume, resolution time, escalation rate) | downline KPIs (counts-only) | org usage/cost KPIs ONLY (no per-agent, no PII) |
| B Alerts | org open stalls + knowledge gaps (counts → links to Escalations) | downline stalls + gaps | **hidden** (alerts reference agent PII) |
| C Recent activity | org rollup summary + recent KB versions | downline rollup summary | org rollup summary only |
| D Quick actions | links to KB, Inventory, Roles, Usage, Conversations, Integrations | links to Agents, Escalations, Coach Analytics | links to Usage & Cost, KB version-history viewer |

**Empty / stale states:**
- Empty (fresh deploy, no rollups yet): reuse the existing `noRollups` pattern — `p.py-8.text-center.text-sm.text-muted-foreground`, copy "No data yet. Metrics appear after the first usage rollup runs." KPI tiles render `—` (em-dash), exactly as `usage-dashboard.tsx` does.
- Stale: reuse the **existing stale-watchdog `Alert`** (`staleWatchdog` + `latestRollupRelative`) verbatim — "Showing data from {relative}. The latest rollup may not have run yet." No new watchdog logic.

## 5. Per-Coach Analytics Pivot (AP-01)

**Surface:** added to the Analytics & Performance coach-analytics view, **admin-only**. A coach **selector** control that filters the read-only aggregation by a chosen coach's downline.

**Control:** reuse the vendored `Select` (same component + sizing as the usage-dashboard window selector — `SelectTrigger className="w-40"` / `w-56` for names). Placed top-right of the analytics section, mirroring the existing window `Select` placement (`flex items-center justify-between gap-4`). Options: "All coaches" (default) + one item per senior-coach (label + short uid).

**Behavior:** changing the selector re-navigates (`router.push(\`/${lang}/...?coach={uid}\`)`) so the RSC re-fetches — identical pattern to `handleWindowChange` in `usage-dashboard.tsx`. The server extends the existing `adminAll` / `seniorCoachId` scoping with a third branch: admin may pass `coachUid` → `base.where('seniorCoachId','==',coachUid)`, still read-only, still `count()`/`select()` aggregation (never fetch-all), still audited (`auditDrilldown`). Non-admin cannot pass the filter (gated server-side — RESEARCH Security Domain).

**Display:** the existing funnel/ramp/gap recharts panels re-render with the scoped data — no new chart types, same indigo/amber palette, same `height={220}` containers. Empty (coach has no downline data): the existing `noRollups`-style centered muted message.

## 6. Integrations Management Shell (SC-01)

**HARD CONSTRAINT:** the shell must expose **NO send / no auto-send / no "connect WhatsApp" affordance** — no button, toggle, switch, or handler that implies messaging. ("No WhatsApp Business API in v1" and "No auto-send, ever" remain in force for Phases 6 & 7.) A render test asserts the **absence** of any send button/handler (RESEARCH Validation: SC-01).

**Route:** new `/${lang}/integrations` under System & Compliance, admin-only, same server-gate pattern (Pattern 1 verbatim). Static — no data model, no Firestore read/write, no Server Action.

**Presentation: empty registry / placeholder.**
```
container mx-auto max-w-4xl px-4 py-8
  H1  "Integrations"
  muted subtitle: "Managed integrations for D2. None are configured."
  Empty-state Card (centered):
    icon (Plug, muted)
    heading "No integrations configured"
    body  "Integrations are a managed, future capability. WhatsApp Business API is
           graduation-gated and not available yet. Replies are always copy-to-clipboard —
           the platform never sends messages on your behalf."
    NO action button.  (Optionally a disabled, non-functional "Coming soon" Badge — NOT a button.)
```
Allowed elements: heading, descriptive copy, a muted icon, a non-interactive `Badge` reading "Coming soon" / "Managed". Forbidden: any `Button`, `Switch`, `Input`, form, or onClick that could read as "send", "connect", "enable", or "authorize".

## 8. Accessibility & Responsive Baseline

**Console posture:** desktop-first management UI (admin/coach/read-only are desktop users). Stay responsive — the vendored sidebar already offcanvas-collapses on mobile via `SidebarTrigger` in `console-shell.tsx` (the `md:hidden` header). Do not regress this.

**Keyboard navigation (sidebar):** the vendored `SidebarMenuButton` is a focusable button/link with `ring-sidebar-ring focus-visible:ring-2` — preserve. Section grouping must not break tab order: tab flows Home → KM items → Agents → … in DOM order. `SidebarGroupLabel`s are non-interactive (correct — they are not tab stops).

**Active-route indication:** vendored `data-active:bg-sidebar-accent data-active:font-medium` (already wired via `isActive`). Sufficient contrast in both `:root` and `.dark` (grayscale tokens). For anchor deep links keep active on the base route.

**Focus states:** rely on the vendored `focus-visible:ring-2` ring on all interactive elements (nav buttons, the coach `Select`, quick-action buttons). Do not remove outlines. The Integrations "Coming soon" badge is non-interactive (not focusable) — correct.

**Color independence:** status in the version timeline must not rely on color alone — the existing chip carries a text label ("Published"/"Superseded") + `line-through`, so it is already non-color-dependent. KPI empty state uses `—` text, not color.

**Responsive grids:** all new grids use the existing breakpoints (`grid-cols-2 md:grid-cols-4`, `md:grid-cols-3`) so they collapse to a single/double column on narrow viewports without horizontal scroll. Tables (per-coach pivot rows) keep the existing `overflow-x-auto` wrapper.
