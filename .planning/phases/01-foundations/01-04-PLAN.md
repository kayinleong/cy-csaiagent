<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → /api/auth/session | Client supplies an ID token; server must verify it before trusting any identity |
| client claim → server authorization | Client-presented role is spoofable; only `verifyIdToken` output is trusted |
| claim-setting → privilege | `setCustomUserClaims` is an elevation primitive; must be Admin-SDK/server-only |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-10 | Spoofing | Forged/expired ID token presented to a privileged route | mitigate | `requireUser`/session route call `adminAuth.verifyIdToken`; fail closed (401) on invalid; unit test asserts the throw |
| T-01-11 | Elevation of Privilege | Client claims a role in the request body | mitigate | Role/tenantId read ONLY from verified token claims; grep gate + unit test confirm body is never the source; rules (01-03) re-check as second boundary |
| T-01-12 | Information Disclosure | ID token / session cookie logged | mitigate | No token/claim logging (grep gate); httpOnly cookie; CLAUDE.md token-hygiene rules |
| T-01-13 | Elevation of Privilege | `set-claims` script misused to grant admin | accept | Script runs only with service-account creds locally by the 2-engineer team; role union validated; documented as the controlled provisioning path (D-11) |
</threat_model>
