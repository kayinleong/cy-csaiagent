<objective>
Extend the `projects` and `collateral` data model so the Finder's two-stage matching, affordability gate, and structured VP queries are physically expressible against Firestore — then back those query shapes with composite indexes and confirm deny-by-default rules still hold.

This is the Wave-1 foundation every other Phase-3 plan builds on. It resolves three RESEARCH schema gaps (Open Questions 2 & 3, Assumptions A3/A4): (1) `priceBand: string` cannot be range-filtered and `findNearest` pre-filters are equality-only, so we add a numeric `priceValue` for in-memory affordability + a discrete equality-filterable `priceBand`; (2) `vpStatus: boolean` cannot answer "completed VP this year", so we add a `vpDate` timestamp; (3) the embedding-text composer needs `description`/`locationText`/`bedrooms` fields that do not exist yet.

Purpose: Make availability + eligibility + affordability + VP-date queries deterministic and indexable (Pattern 4, Pattern 7, Pitfall 6). No matching logic here — just the schema + indexes + rules safety net.
Output: Extended `ProjectDoc`/`CollateralDoc`, two new `projects` composite indexes, extended rules-unit-tests.
</objective>
