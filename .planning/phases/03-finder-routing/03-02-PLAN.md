<objective>
Build the single most important Phase-3 module: a two-stage `searchProjects` where availability + eligibility + affordability are DETERMINISTIC Firestore filters that run FIRST, and Gemini `findNearest` similarity only RE-RANKS within the already-eligible set. This makes sold-out / hidden / bumi-reserved / foreign-ineligible / unaffordable projects physically unreachable, not merely deprioritized (Pattern 4, Pitfalls 1/3/4/6).

Also build the structured `queryInventory` path (FIND-07 "completed VP this year" — no vector), the project embedding-text composer + embedder, and segment-aware ranking (FIND-09 investment vs own-stay).

This is a TDD plan: the active-only / affordability / segmentation invariants are exactly `expect(searchProjects(input)).toMatchObject(output)` assertions — write them RED first.

Purpose: A grounded matching engine that cannot recommend a bad match (SC1, SC3). The Finder agent (03-04) and admin re-embed (03-03) consume it.
Output: `src/inventory/search.ts`, `src/inventory/embedText.ts`, `src/inventory/index.ts`, `src/inventory/search.test.ts`.
